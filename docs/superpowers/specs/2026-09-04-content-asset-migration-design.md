# Content & Asset Migration — Design

## Background

The "Site Foundation" plan (`docs/superpowers/specs/2026-09-04-new-site-design.md`,
`docs/superpowers/plans/2026-09-04-site-foundation.md`) is complete: a Next.js app with a
grayscale design system, Sanity CMS with 5 content schemas, and placeholder pages for
every site-map route, deployed to Vercel staging.

Before any real page design work happens, the Sanity CMS needs real content. This plan
covers *only* getting real data into Sanity — no frontend page changes. The next plan
("page-by-page design build") builds the actual page layouts against this real content.

## Source site audit

Re-examined the live site (theproperpainter.com, built on Durable) with a real browser
(the earlier plain-HTML fetch during brainstorming missed everything below, since Durable
lazy-loads content via JS):

- **Actual nav/site map differs slightly from the original site-map assumption:** the live
  nav is About, Services, "Portfolio & Testimonials" (→ `/portfolio`), Contact. The `/team`
  URL actually renders an "Our Reviews" page, not a team roster — there is no dedicated
  team-bios page on the live site. Only Elizabeth is profiled (on `/about`); a colleague
  named "May" is mentioned in passing within two testimonials, with no separate bio.
- **Contact info:** phone `412-427-6873` is public on the site. No email is published
  publicly (only a contact form) — the real business email was provided directly:
  `theproperpainterllc@gmail.com`.
- **Social links found:** HomeAdvisor listing, Facebook (`facebook.com/theproperpainterllc`),
  Instagram (`instagram.com/theproperpainterllc`), a Google review link
  (`g.page/r/CQ7RtRHDEUczEAE/review`). A Publuu flipbook brochure link
  (`online.publuu.com/528844/1212275`) was checked and is dead (HTTP 410) — not usable as a
  photo source.
- **Real logo asset found:** a circular badge logo (paintbrush illustration, "WOMAN OWNED &
  OPERATED, EST. 2020", tagline "I might not be proper, but... my paint job is.").
- **Additional testimonials found** on the live `/team` ("Our Reviews") page beyond
  HomeAdvisor's 23: Michele S. and Robyn F. — not obviously present on the HomeAdvisor
  listing.
- **No explicit before/after photo pairs** exist anywhere on the live site — only single
  "after"/showcase shots, contextually associated with rooms (kitchen, bathroom, living
  room, staircase, etc.) via `<img alt="...">` text.

## Decisions

| Area | Decision |
|---|---|
| Scope | Backend/CMS content only — no Next.js page/template changes in this plan |
| Reviews | Merge HomeAdvisor's 23 reviews (source: "HomeAdvisor" — name, date, star rating, service type, price, full text) with the 2 extra found on the live site's own reviews page (Michele S., Robyn F. — source: "Direct") into the `testimonial` schema |
| Logo | Pull the real circular badge logo as a Sanity image asset (referenced from `siteSettings` or a dedicated field) for use in a future page-design pass — not applied to any page template in this plan |
| Portfolio photos | Populate `portfolioProject.afterImage` only for now; `beforeImage` stays empty until Elizabeth can supply real before shots. Category inferred from image `alt` text / page context (e.g. "kitchen cabinets" → Cabinet Painting) |
| Site settings | Populate the `siteSettings` singleton: `contactPhone` (412-427-6873), `contactEmail` (theproperpainterllc@gmail.com), `socialLinks` (HomeAdvisor, Facebook, Instagram, Google reviews — Publuu excluded, dead link) |
| Team | One `teamMember` document for Elizabeth, using her existing `/about` bio content. "May" is not added as a formal team member (no bio content exists for her) — can be added later if Elizabeth wants |
| `/team` route repurposing | Decision recorded for the *next* plan: `/team` will display reviews/testimonials (matching what the live site actually does), not a team roster — this plan only ensures the `testimonial` data exists in Sanity; the page template change is out of scope here |
| Migration mechanism | A one-off Node/TypeScript script (not part of the running Next.js app) using Playwright to crawl the live site for real image URLs (bypassing Durable's lazy-load placeholders) + alt text, downloading images, uploading them to Sanity via `client.assets.upload()`, and creating/updating the Sanity documents via a write-token-authenticated Sanity client |
| Sanity write access | Requires a **Sanity API token with write access**, generated by a human via sanity.io/manage → API → Tokens — cannot be done by an agent (same class of manual step as the original project creation) |

## Out of scope

- Any change to Next.js page templates/layouts (that's the next plan)
- Before/after photo pairs (until Elizabeth supplies real before shots)
- A full team-bios page/section beyond Elizabeth (no source content exists for other staff)
- DripJobs/Zapier lead-capture integration
- Launch QA / DNS cutover

## QA before considering this plan done

- Every migrated image asset opens correctly in Sanity Studio and displays a reasonable
  preview (not broken/corrupted)
- Testimonial count in Sanity equals 25 (23 HomeAdvisor + 2 direct), each with a real
  quote, author, and source tag — no placeholder/lorem-ipsum text
- `siteSettings` singleton has correct phone, email, and all 4 working social links
- The `teamMember` document for Elizabeth has real bio text pulled from the live `/about`
  page, not placeholder text
